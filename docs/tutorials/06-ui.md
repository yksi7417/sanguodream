# 06 UI: panels that only call the api

Files: code/ui/ui.h, ui.cpp, ui_map.cpp. Tests: tests/ui/ui_tests.cpp
(8 tests) with tests/ui/engine_recorder.h.

## What it is for
This tutorial covers the Dear ImGui panels. Each panel reads through
`engine_api` queries and reacts to clicks with `engine_api` commands. That
is the whole job, so that is what the UI tests check.

## Read it in this order
1. ui.h: `ui_state` (the open windows, the map selection) lives in the
   game's permanent memory, so it survives DLL reloads. `ui_frame_info`
   carries front-end facts (frame time, reload count, frame arena usage)
   that are not the engine's business.
2. ui.cpp: `ui_draw` calls one function per panel. `ui_draw_simulation` is
   the smallest: two queries, two buttons, each button one command.
3. `ui_draw_ledger`: a table that `ledger_count` and `ledger_at` feed, with
   a clipper, so the panel fetches only the visible rows. The ui test counts
   the `ledger_at` calls to prove exactly one call per event.
4. ui_map.cpp: draws every cell with `cell_cost`, picks cells with
   `hex_from_pixel`, and shows `path_cost` between two picks. Nothing here
   knows what a cost means.

## How the UI tests work
tests/ui/engine_recorder.h implements `engine_api`. It appends every call
to an array and answers from scripted state (a fake 8x6 map, canned
events). `ui_tests.exe` does four things. It creates an ImGui context with
no renderer. It builds the font atlas by hand. It starts the Dear ImGui Test
Engine. Then it registers tests. The `GuiFunc` of each test draws the real
panels against the recorder. The `TestFunc` clicks things and asserts on
the recorded calls.

Read `advance_turn_calls_end_turn` first: reset the recorder, click the
button, expect one `end_turn`, one command in total, nothing dropped.
Then:
- `advance_12_calls_advance_turns_12`: the test checks the argument too.
- `ledger_clear_calls_ledger_clear`.
- `ledger_reads_every_event_through_api`: 7 events, 7 `ledger_at` calls,
  zero commands. A draw must never command.
- `window_menu_toggles_without_commands`: menus change `ui_state` only.
- `map_panel_reads_every_cell_and_commands_nothing`: 48 `cell_cost` calls
  for the 8x6 fake map, no `path_cost` before a selection exists.
- `idle_frames_command_nothing`: ten idle frames, zero commands.
- The one `e2e` test puts the real engine behind the panels and checks the
  turn and ledger after a click. Keep that category tiny.

## Exercises
- Add a "Advance 12 turns" confirmation popup and update the ui test so the
  command is issued only after confirming.
- Write a ui test that clicks two cells on the map through the test engine
  (`ctx->MouseMoveToPos` with coordinates from `hex_to_pixel`) and asserts
  exactly one `path_cost` call per frame afterwards.
